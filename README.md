# Перемена

Небольшой мессенджер для общения внутри школы. Личные диалоги и групповые чаты,
сообщения приходят мгновенно, работает в браузере — и на компьютере, и с телефона.

## Что умеет

**Переписка**
- Личные диалоги один-на-один и групповые чаты
- Мгновенная доставка без перезагрузки страницы
- Ответы с цитированием, редактирование и удаление своих сообщений
- Реакции эмодзи
- Вложения: картинки (показываются прямо в ленте), документы, PDF
- Поиск по всем своим перепискам и по людям

**Мелочи, из которых складывается ощущение живого мессенджера**
- Кто сейчас в сети и «был(а) 5 минут назад»
- «Печатает…»
- Счётчики непрочитанного и черта «Непрочитанные» в ленте
- Галочки «отправлено / прочитано»
- Уведомления в браузере, когда вкладка свёрнута
- Тёмная и светлая темы
- Раскладка под телефон, можно поставить на домашний экран как приложение
- Группы «без звука»

**Управление**
- Свободная регистрация (по умолчанию) или закрытый режим по кодам-приглашениям
- Создатель группы переименовывает её, добавляет и убирает участников
- Первый зарегистрировавшийся становится администратором

## Быстрый старт

Нужен Node.js 20+ и любая база PostgreSQL.

```bash
npm install
cp .env.example .env.local     # укажите DATABASE_URL и AUTH_SECRET
npm run db:push                # создать таблицы
npm run dev                    # http://localhost:3000
```

Секрет для кук удобно сгенерировать так:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Хотите сразу посмотреть на заполненный интерфейс, не регистрируя всех вручную:

```bash
npm run db:seed   # 4 демо-аккаунта, пароль у всех: peremena-demo
```

## Развёртывание на Vercel + Neon

1. **Заведите базу.** В [Neon](https://console.neon.tech) создайте проект и
   скопируйте строку подключения — ту, где в адресе есть `-pooler`.
   Подойдёт и Vercel Postgres, и Supabase, и свой сервер: код обычный
   PostgreSQL, ничего специфичного для Neon в нём нет.

2. **Создайте таблицы.** С той же строкой подключения выполните локально:

   ```bash
   DATABASE_URL="postgresql://…" npm run db:push
   ```

3. **Залейте проект на Vercel** (импорт репозитория с GitHub) и пропишите
   переменные окружения:

   | Переменная | Зачем |
   |---|---|
   | `DATABASE_URL` | Строка подключения к базе (обязательно) |
   | `AUTH_SECRET` | Случайная строка от 32 символов для подписи сессий (обязательно) |
   | `INVITE_ONLY` | `true` — регистрация только по коду. По умолчанию открытая |
   | `ADMIN_USERNAME` | Кому выдать права администратора при регистрации |
   | `REGISTRATION_LIMIT` | Сколько регистраций в час с одного адреса (по умолчанию 60) |

4. Откройте адрес и зарегистрируйтесь первым — этот аккаунт получит права
   администратора.

Никакой отдельной настройки Vercel не требуется: приложение обходится обычными
маршрутами Next.js и не нуждается в WebSocket-сервере (см. ниже).

## Как это устроено

Обычное приложение на Next.js (App Router) и PostgreSQL. Внешних сервисов нет,
из зависимостей — только Next, React и драйвер `pg`.

```
src/lib/         работа с базой, сессии, проверка ввода, лента событий
src/app/api/     маршруты API
src/components/  интерфейс
db/schema.sql    схема базы
scripts/         применение схемы и демо-данные
tests/           модульные и сквозные проверки
```

Три решения, которые стоит пояснить.

**Мгновенная доставка без WebSocket.** На serverless-хостинге вроде Vercel негде
держать постоянный сокет и общую шину между экземплярами функции. Поэтому
источник правды — таблица `events` в базе: любое изменение пишет туда строку, а
клиенты читают её по курсору через Server-Sent Events. Экземпляры ничего не
знают друг о друге, при обрыве связи ничего не теряется (браузер сам присылает
`Last-Event-ID`), и ровно тот же код работает на своём сервере. Задержка — доли
секунды: пока идёт разговор, лента опрашивается часто, в тишине реже.

**Файлы лежат в базе.** У serverless нет постоянного диска, а заводить отдельное
хранилище ради школьного чата — лишняя деталь, которую придётся настраивать и
оплачивать. Файлы хранятся в Postgres с ограничением 8 МБ на файл. Если объёмы
вырастут, менять придётся только `src/app/api/files/`.

**Пароли и сессии.** Пароли хешируются `scrypt` со случайной солью. В куке лежит
случайный токен, в базе — только его HMAC, так что утечка таблицы сессий не даёт
готовых кук. Кука `httpOnly`, `sameSite=lax`, в продакшене `secure`.

## Тесты

Модульные проверки чистых функций — запускаются сразу:

```bash
npm test
```

Сквозные проверки API ходят по настоящему HTTP, поэтому им нужны отдельная база
и запущенный сервер:

```bash
createdb peremena_test
DATABASE_URL="postgresql://localhost/peremena_test" npm run db:push
DATABASE_URL="postgresql://localhost/peremena_test" AUTH_SECRET="test-secret-0123456789abcdef" \
  npx next start -p 3100 &
BASE_URL=http://127.0.0.1:3100 npm run test:api
```

Они проверяют в том числе то, что легко сломать незаметно: посторонний не
читает чужую переписку и не скачивает чужие вложения, удалённое сообщение не
уезжает клиенту вместе с текстом, загруженный HTML отдаётся как обычный текст и
не может выполниться на нашем домене.

## О безопасности — что стоит знать

- **Регистрация сейчас открытая.** Зарегистрироваться может любой, кто узнает
  адрес. Для школы это осознанный выбор простоты; если понадобится закрыть круг,
  поставьте `INVITE_ONLY=true` — тогда нужен код-приглашение из таблицы
  `invites`. Коды заводятся вручную:

  ```sql
  INSERT INTO invites (code, max_uses) VALUES ('SHKOLA-2026', 30);
  ```

- **Переписка не зашифрована сквозным шифрованием.** Сообщения лежат в базе
  открытым текстом, и тот, у кого есть доступ к базе, их прочитает. Для
  школьного чата это обычная ситуация (так же устроено большинство мессенджеров
  без E2E), но обещать детям тайну переписки не стоит.

- **Администратор может удалять чужие сообщения**, но не читать чужие личные
  диалоги через интерфейс.
