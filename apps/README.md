# Приложения «ГимРум»

Здесь лежат обёртки для телефона и компьютера. Обе открывают тот же сайт и
ходят в тот же API, поэтому переписка, аккаунты и группы общие: отправленное с
телефона видно в окне на компьютере и в браузере.

**Прямого доступа к базе у приложений нет и не будет.** Строка подключения
лежала бы внутри файла, а `.apk` распаковывается за минуту любым архиватором —
это был бы пароль ко всей переписке гимназии, розданный вместе с программой.
Приложения знают только адрес сайта.

## Android (`android/`)

Trusted Web Activity, собранная через [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap).
Содержимое обновляется вместе с сайтом — переустанавливать APK после правок
не нужно, новая версия нужна только при смене адреса, значка или названия.

Чтобы адресная строка не показывалась, сайт подтверждает родство с приложением
файлом `public/.well-known/assetlinks.json`: в нём отпечаток того самого ключа,
которым подписан APK. Сменится ключ — надо обновить и файл.

Сборка:

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export ANDROID_HOME=/путь/к/android-sdk
cd apps/android
./gradlew assembleRelease

# Выравнивание и подпись
BT=$ANDROID_HOME/build-tools/36.1.0
"$BT/zipalign" -p -f 4 app/build/outputs/apk/release/app-release-unsigned.apk aligned.apk
"$BT/apksigner" sign --ks android.keystore --ks-key-alias gimroom \
  --out gimroom.apk aligned.apk
```

`android.keystore` в репозиторий не попадает (см. `.gitignore`) — по нему
выпускают обновления, и его утечка позволила бы подделать приложение от имени
гимназии. Храните его вместе с паролем там же, где остальные ключи от проекта.
Потеряете — новые версии придётся ставить как отдельное приложение, поверх
старого они не встанут.

Версия приложения задаётся в `app/build.gradle` (`versionCode`, `versionName`).
`versionCode` должен расти с каждой выкладкой, иначе Android откажется
обновлять.

## Windows (`desktop/`)

Electron: окно с сайтом, свой значок, ссылки из сообщений открываются в
браузере, а не подменяют окно мессенджера.

```bash
cd apps/desktop
npm install
npx electron-builder --win --dir     # портативная папка в dist/
```

Готовый установщик (`--win nsis`) собирается только на самой Windows: на Linux
для этого нужен Wine, и он же нужен, чтобы вписать значок и название внутрь
`.exe`. Без него файл получается со стандартным значком Electron — на работу
это не влияет, значок окна и панели задач берётся из `build/icon.png`.

Адрес сайта можно переопределить переменной `GIMROOM_URL` — пригодится, если
гимназия переедет на свой домен.

## Windows, основной вариант (`native/` + `bundle/`)

Собственное окно приложения: свой заголовок, свой значок в панели задач,
никакой адресной строки и вкладок. Страницу рисует WebView2 — движок, который
уже стоит в Windows 10 и 11 вместе с Edge, поэтому программа весит около
мегабайта, а не сто с лишним, как сборка со своим встроенным браузером.

Куки и локальные данные лежат в `%LOCALAPPDATA%\GimRoom`, а не рядом с
программой: её кладут и в Program Files, и на флешку, где прав на запись может
не быть — тогда вход не сохранялся бы между запусками. Заодно у каждого
пользователя Windows свои данные, что важно на общем компьютере.

Рядом с приложением обязана лежать `WebView2Loader.dll` — без неё Windows не
запустит его вовсе. Носить два файла и объяснять, что их нельзя разделять, —
верный способ получить «у меня не работает», поэтому `bundle/` вшивает оба
внутрь себя, разворачивает при запуске в папку пользователя и стартует
приложение оттуда. Наружу это один exe.

Со статической линковкой загрузчика (она избавила бы от лишнего шага) ничего
не вышло: библиотека Microsoft собрана MSVC и требует его же C++-рантайм,
которого у mingw нет. Воспроизводить его ради одного файла — плохой размен.

```bash
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu

# 1. Само приложение
cd apps/native
cargo build --release --target x86_64-pc-windows-gnu
mkdir -p dist
cp target/x86_64-pc-windows-gnu/release/gimroom.exe dist/
cp ~/.cargo/registry/src/*/webview2-com-sys-*/x64/WebView2Loader.dll dist/

# 2. Один файл, который несёт приложение в себе
cd ../bundle
cargo build --release --target x86_64-pc-windows-gnu

# 3. Готовое — в apps/dist, и раздают только оттуда
cd ../..
mkdir -p apps/dist
cp apps/bundle/target/x86_64-pc-windows-gnu/release/gimroom-setup.exe \
   apps/dist/gimroom-windows.exe
```

**Людям отдают только `apps/dist/gimroom-windows.exe`.** Файл из
`native/dist/` — это заготовка для сборки, а не программа: он требует
`WebView2Loader.dll` рядом с собой, и запущенный сам по себе встречает
человека системной ошибкой «не удаётся продолжить выполнение кода».
Проверить, что перед вами настоящий одиночный файл, можно по списку
зависимостей — `WebView2Loader.dll` в нём быть не должно:

```bash
llvm-objdump -p apps/dist/gimroom-windows.exe | grep 'DLL Name'
# только KERNEL32, msvcrt, ntdll и api-ms-win-core-*
```

Адрес сайта задан константой `SITE` в `native/src/main.rs`.

## Windows, запасной вариант (`launcher/`)

Открывает сайт в окне Edge (`--app`): без адресной строки и вкладок, но это
всё-таки браузер, а не своё окно. Держим на случай, если WebView2 где-то
окажется недоступен, — как самый простой из работающих вариантов.

Профиль браузера берётся обычный, не отдельный: если человек уже вошёл в
мессенджер в браузере, приложение откроется под его аккаунтом сразу.

Сборка с Linux (нужны `mingw-w64` и таргет `x86_64-pc-windows-gnu`):

```bash
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu

cd apps/launcher
x86_64-w64-mingw32-windres app.rc -O coff -o app.res
rustc --target x86_64-pc-windows-gnu -C opt-level=z -C strip=symbols \
  -C panic=abort -C link-arg=app.res main.rs -o "ГимРум.exe"
```

Значок берётся из `../desktop/build/icon.ico` — второй копии в репозитории
намеренно нет. Адрес сайта задан константой `SITE` в `main.rs`.

Electron-вариант выше не зависит ни от Edge, ни от WebView2 — но платит за это
стомегабайтным размером.
